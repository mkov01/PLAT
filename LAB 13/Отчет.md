## ⚙️ Входные и выходные данные

### Вариант №1 (Базовый уровень — Список покупок):
* **Входные данные:** Название товара, категория, количество и цена при добавлении; название товара для удаления (без учёта регистра); команды просмотра списка, отмены последнего действия и экспорта в JSON.
* **Выходные данные:** Обновлённый список покупок, статистика по количеству и сумме, сообщения об успешном добавлении/удалении, а также обработка ошибок при попытке удаления из пустого списка или поиска несуществующего товара.

### Вариант №15 (Средний уровень — Мини-библиотека):
* **Входные данные:** Уникальный идентификатор книги (`ID`), название, автор и год при регистрации новой книги; `ID` книги и имя читателя при оформлении выдачи; `ID` книги при возврате; фильтр отображения только доступных книг.
* **Выходные данные:** Словарь каталога книг с актуальными статусами («В наличии» / «Выдана»), перечень доступных для выдачи экземпляров и обработка исключительных ситуаций (несуществующий `ID`, дубликат ключа, повторная выдача занятой книги).

### Вариант №17 (Повышенный уровень — История браузера):
* **Входные данные:** Адрес страницы (`URL`) и заголовок при переходе на новую страницу; команды навигации «Назад» (`Back`) и «Вперёд» (`Forward`).
* **Выходные данные:** Текущая активная страница, актуальное состояние двух стеков (`back_stack` и `forward_stack`), автоматическая очистка стека «Вперёд» при новом переходе и блокировка навигации при пустых стеках.

## 🧱 Обоснование выбора структур данных

| Вариант | Выбранная структура данных | Обоснование выбора |
| :---: | :--- | :--- |
| **№1** | **Список (`list`)** + вспомогательный стек отмены (`list` / LIFO) | Список сохраняет порядок добавления товаров, поддерживает быстрое добавление в конец (`append()` за `O(1)`), последовательный перебор для просмотра всех позиций и удаление по значению. Дополнительный стек позволяет откатывать последнее действие по принципу LIFO. |
| **№15** | **Вложенный словарь (`dict`)** вида `{ID: {"title": ..., "available": ...}}` | Каждая книга имеет уникальный ключ (`ID`), поэтому словарь обеспечивает мгновенный доступ, проверку наличия и изменение статуса выдачи/возврата в среднем за `O(1)` без перебора всего фонда. |
| **№17** | **Два стека (`back_stack` и `forward_stack`)** на базе `list` (принцип **LIFO**) | Переход «Назад» должен возвращать самую последнюю посещённую страницу (последней пришла — первой ушла). Использование двух стеков позволяет за `O(1)` перекладывать URL между историей возврата и историей перехода вперёд, а при открытии новой ссылки мгновенно очищать `forward_stack.clear()`. |

## 🛠️ Алгоритм решения
1. **Проектирование структур данных:** Выбор оптимальных коллекций под каждую задачу (`list` для упорядоченного списка покупок, вложенный `dict` для каталога библиотеки по `ID`, пара стеков `LIFO` для навигации браузера).
2. **Реализация базовых операций CRUD и LIFO:** Программирование функций добавления, поиска, просмотра, изменения состояния и удаления элементов с нормализацией строкового ввода (`strip()`, `lower()`).
3. **Обработка граничных случаев и ошибок:** Добавление проверок на пустые коллекции, пустой ввод, дубликаты ключей/элементов, обращение к отсутствующим названиям и `ID`, а также недопустимые переходы при пустых стеках `back`/`forward`.
4. **Реализация дополнительных функций и интерактивных прототипов:** Добавление отката последнего действия (Undo), фильтрации, журналов операций и экспорта состояния коллекций в формат `JSON` в интерактивных веб-приложениях (`Задание 1.html`, `Задание 15.html`, `Задание 17.html`).
