### 17. Что такое HTML-форма?
**HTML-форма** — это специальная область веб-страницы, ограниченная тегами `<form>...</form>`, предназначенная для сбора структурированных данных от пользователя и их последующей передачи на сервер или локальной обработки скриптами (JavaScript).

---

### 18. Для чего используются элементы input, select и button?
Каждый элемент выполняет свою роль в интерфейсе:
*   **`input`** — универсальный элемент для ввода данных (текста, email, паролей, чисел) или переключения флагов (чекбоксы, радиокнопки).
*   **`select`** — формирует раскрывающийся список выбора (выпадающее меню), позволяя пользователю выбрать один или несколько готовых вариантов.
*   **`button`** — интерактивная кнопка для выполнения действий. С атрибутом `type="submit"` она инициирует отправку данных текущей формы.

---

### 19. Чем checkbox отличается от radio?
*   **`checkbox` (флажок)** — используется для выбора **независимых параметров**. Пользователь может выбрать несколько чекбоксов одновременно или не выбрать ни одного.
*   **`radio` (переключатель)** — используется для выбора **одного взаимоисключающего варианта из группы**. Чтобы радиокнопки работали в связке, у них должен быть строго одинаковый атрибут `name`.

---

### 20. Что такое клиентская валидация?
Это автоматическая проверка корректности данных (на заполненность, длину, формат), которая происходит **непосредственно в браузере пользователя** до того, как форма уйдет на сервер. Реализуется средствами HTML5 (атрибуты `required`, `pattern`) или скриптами JavaScript.

---

### 21. Для чего используется событие submit?
Событие **`submit`** генерируется формой в момент попытки ее отправки (например, клик по кнопке с `type="submit"` или нажатие Enter). Перехват этого события в JavaScript позволяет остановить стандартный процесс, проверить данные и показать ошибки, если они есть.

---

### 22. Что делает event.preventDefault()?
Этот метод **отменяет стандартное поведение браузера**, предусмотренное для данного события. Применительно к событию `submit` он блокирует автоматическую перезагрузку страницы и отправку данных на сервер, давая возможность отработать JS-валидатору.

---

### 23. Как получить значение текстового поля в JavaScript?
Значение считывается через свойство **`.value`** у ссылки на DOM-элемент этого поля.
```javascript
const userFio = document.getElementById('bookFio').value;
```

---

### 24. Как проверить состояние checkbox?
Состояние флажка проверяется с помощью логического свойства **`.checked`**. Оно возвращает `true`, если галочка установлена, и `false`, если снята.
```javascript
const isAgreed = document.getElementById('studAgree').checked;
```

---

### 25. Как получить выбранное значение select?
Аналогично текстовому полю — через обращение к свойству **`.value`** самого элемента `<select>`. Оно возвращает строку, указанную в атрибуте `value` активного в данный момент тега `<option>`.
```javascript
const category = document.getElementById('bookCategory').value;
```

---

### 26. Почему клиентская валидация не заменяет серверную?
Клиентская валидация работает на стороне пользователя, а значит, **ее легко обойти**: отключить JavaScript в браузере, изменить код через инструменты разработчика (F12) или отправить поддельный запрос напрямую на сервер через специальные утилиты (Postman, cURL). Серверная валидация обязательна, так как она является главным рубежом безопасности базы данных и системы.

---

### 27. Как сделать сообщение об ошибке понятным пользователю?
*   **Локализация:** Ошибка должна отображаться рядом с конкретным невалидным полем.
*   **Четкий контекст:** Не пишите просто *"Ошибка"*. Напишите конкретное требование, например: *"Пароль должен быть не менее 8 символов"*.
*   **Визуальный акцент:** Выделяйте неверные поля и сообщения об ошибках контрастным цветом (обычно красным) для привлечения внимания.

---

### 28. Какие тестовые случаи следует проверить для формы?
Для полной проверки качества валидации необходимо протестировать минимум 4 сценария:
1.  **Успешный (Happy Path):** Ввод абсолютно корректных данных во все поля (форма должна успешно отправляться).
2.  **Пустые поля:** Попытка отправки с незаполненными обязательными полями (должны сработать триггеры ошибок).
3.  **Неверный формат:** Ввод некорректного email (без `@` или домена) или букв в числовые поля.
4.  **Граничные условия:** Проверка логики паролей (ввод 7 символов вместо 8, ввод несовпадающих паролей).
