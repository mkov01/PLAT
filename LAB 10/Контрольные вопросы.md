Ответы на контрольные вопросы (Лабораторная работа №10)Что такое модуль в JavaScript?Ответ: Модуль — это отдельный JS-файл, выполняемый в собственном изолированном пространстве имен (модульной области видимости). Переменные, функции и классы, объявленные внутри модуля, по умолчанию недоступны снаружи, пока они явно не будут экспортированы с помощью оператора export.   Чем ES-модули отличаются от обычных скриптов?Ответ:Область видимости: В обычных скриптах глобальные переменные попадают в общий объект window. В ES-модулях видимость ограничена самим файлом.Строгий режим: Модули всегда автоматически выполняются в строгом режиме ("use strict").   Отложенная загрузка: Модульные скрипты по умолчанию имеют поведение defer (выполняются только после полной загрузки HTML-дерева).Повторное выполнение: Модуль загружается и выполняется браузером только один раз при первом импорте, независимо от количества точек импорта.Для чего нужен type="module"?Ответ: Атрибут type="module" в теге <script> сообщает браузеру, что загружаемый файл является ES-модулем. Это включает поддержку синтаксиса import/export, включает строгий режим и изменяет обработку CORS и отложенную загрузку.   Как работает именованный export?Ответ: Именованный экспорт (export function foo() {} или export { a, b }) позволяет экспортировать несколько сущностей из одного файла под их конкретными именами. При импорте названия импортируемых элементов должны строго совпадать с экспортируемыми и оборачиваться в фигурные скобки: import { foo } from './module.js'.   Чем default export отличается от named export?Ответ:default export (по умолчанию): В модуле может быть только один экспорт по умолчанию (export default function() {}). При импорте фигурные скобки не используются, а импортируемой сущности можно дать любое произвольное имя.   named export (именованный): Может быть много в одном файле. Импортируется строго по названию в фигурных скобках { name }.   Почему важен путь к импортируемому файлу?Ответ: В браузерных ES-модулях пути к файлам должны обязательно быть относительными (./ или ../) или абсолютными URL. Браузер не умеет автоматически искать файлы в папках проекта (в отличие от Node.js без сборщиков), поэтому полное указание расширения файла (например, ./modules/cart.js) необходимо для точного сетевого HTTP-запроса к серверу.   Что такое область видимости модуля?Ответ: Это локальная область видимости верхнего уровня (top-level scope) конкретного JS-файла. Переменные, функции и классы, созданные внутри модуля, изолированы и не загрязняют глобальный объект window.Почему модульное приложение удобнее сопровождать?Ответ:Код логически разделен на небольшие независимые файлы (принцип единственной ответственности).   Улучшается читаемость и навигация по проекту.Проще переиспользовать код в других частях системы.Снижается риск конфликтов имен переменных и функций.Зачем отделять бизнес-логику от DOM?Ответ: Чтобы вычисления и обработка данных (бизнес-логика) не зависели от верстки и элемента интерфейса. Это позволяет менять дизайн HTML/CSS или переходить на другие фреймворки без переписывания математики/алгоритмов приложения, а также облегчает автоматическое тестирование.   Как диагностировать ошибку загрузки модуля?Ответ: Через инструменты разработчика в браузере (DevTools):Вкладка Console: Показывает синтаксические ошибки и CORS-блокировки.   Вкладка Network: Показывает HTTP-статусы загрузки файлов (например, 404 Not Found при некорректном пути).   Почему рекомендуется запускать проект через HTTP-сервер?Ответ: При открытии HTML-файла напрямую через протокол file:// браузер в целях безопасности (Политика Same-Origin / CORS) блокирует загрузку внешних ES-модулей с диска. Локальный HTTP-сервер (например, python -m http.server или Live Server) отдает файлы по протоколу http://localhost, что позволяет браузеру безопасно выполнять import.   Что такое циклическая зависимость модулей?Ответ: Это ситуация, при которой двух или более модулей взаимно зависят друг от друга (например, модуль А импортирует модуль Б, а модуль Б импортирует модуль А). Это может приводить к ошибкам неопределенности (undefined), неинициализированным переменным или бесконечным циклам вызова.
