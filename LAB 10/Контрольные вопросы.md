### 📌 Вопрос 1. Что такое модуль в JavaScript?
**Ответ:**  
Модуль — это отдельный файл JavaScript, выполняемый в собственном изолированном пространстве имен (модульной области видимости). Переменные, функции и классы, объявленные внутри модуля, по умолчанию локальны и недоступны снаружи, пока они не будут явно экспортированы с помощью оператора `export`.

---

### 📌 Вопрос 2. Чем ES-модули отличаются от обычных скриптов?
**Ответ:**
* **Область видимости:** В обычных скриптах переменные верхнего уровня попадают в глобальный объект `window`. В ES-модулях область видимости ограничена текущим файлом.
* **Строгий режим:** ES-модули автоматически выполняются в строгом режиме (`"use strict"`).
* **Отложенное выполнение:** Модульные скрипты по умолчанию загружаются с поведением `defer` (выполняются после построения DOM-дерева).
* **Однократное выполнение:** Модуль загружается и исполняется браузером строго **один раз** при первом импорте.

---

### 📌 Вопрос 3. Для чего нужен `type="module"`?
**Ответ:**  
Атрибут `type="module"` в теге `<script>` сообщает браузеру, что загружаемый файл является ES-модулем. Это активирует поддержку синтаксиса `import`/`export`, строгий режим работы, отложенную загрузку и обработку файлов по правилам CORS.

---

### 📌 Вопрос 4. Как работает именованный `export`?
**Ответ:**  
Именованный экспорт (`export function foo() {}` или `export { name1, name2 }`) позволяет экспортировать несколько сущностей из одного модуля. При импорте названия сущностей должны строго совпадать и оборачиваться в фигурные скобки: `import { foo } from './module.js'`.

---

### 📌 Вопрос 5. Чем `default export` отличается от `named export`?
**Ответ:**
* **`default export` (экспорт по умолчанию):** В модуле может быть только **один** экспорт по умолчанию (`export default function() {}`). При импорте фигурные скобки **не используются**, а импортируемой сущности можно присвоить любое имя: `import MyFunc from './module.js'`.
* **`named export` (именованный экспорт):** Позволяет экспортировать **множество** элементов из файла, а импортируются они строго по именам в фигурных скобках: `import { a, b } from './module.js'`.

---

### 📌 Вопрос 6. Почему важен путь к импортируемому файлу?
**Ответ:**  
В браузерных ES-модулях пути к файлам должны обязательно указываться относительно (`./` или `../`) или как абсолютные URL. Браузер осуществляет сетевой HTTP-запрос по указанному пути, поэтому необходимо явно прописывать полное расширение файла (например, `./modules/tasks.js`), иначе файл не будет найден (ошибка 404).

---

### 📌 Вопрос 7. Что такое область видимости модуля?
**Ответ:**  
Это локальная область видимости верхнего уровня (top-level scope) конкретного JS-файла. Переменные и функции, объявленные в модуле, не загрязняют глобальный объект `window` и не перекрывают переменные из других файлов.

---

### 📌 Вопрос 8. Почему модульное приложение удобнее сопровождать?
**Ответ:**
1. **Декомпозиция:** Код разделен на небольшие логические блоки по принципу единственной ответственности.
2. **Переиспользование:** Функции из одного модуля можно легко импортировать в другие части проекта.
3. **Безопасность имен:** Исключаются случайные конфликты одинаковых имен переменных.
4. **Удобство отладки:** Проще локализовать ошибку в конкретном маленьком файле.

---

### 📌 Вопрос 9. Зачем отделять бизнес-логику от DOM?
**Ответ:**  
Чтобы вычисления, алгоритмы и обработка данных (бизнес-логика) не зависели от элементов страницы (HTML/CSS). Это позволяет менять верстку или переходить на другой UI-фреймворк без изменения логики расчетов, а также проводить модульное автоматическое тестирование (Unit Testing).

---

### 📌 Вопрос 10. Как диагностировать ошибку загрузки модуля?
**Ответ:**  
С помощью инструментов разработчика браузера (DevTools):
* **Вкладка Console:** Показывает ошибки синтаксиса, отсутствие экспортируемых элементов и CORS-блокировки.
* **Вкладка Network:** Показывает статус HTTP-запроса (например, ошибку 404 Not Found, если путь к модулю указан неверно).

---

### 📌 Вопрос 11. Почему рекомендуется запускать проект через HTTP-сервер?
**Ответ:**  
При открытии HTML-файла напрямую с диска по протоколу `file://` браузер блокирует загрузку ES-модулей из соображений безопасности (Политика Same-Origin / CORS). Запуск через локальный HTTP-сервер (например, `python -m http.server` или Live Server) обеспечивает работу
