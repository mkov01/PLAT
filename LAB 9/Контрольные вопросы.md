8. Что такое AJAX и REST API?
AJAX (Asynchronous JavaScript and XML) — это подход к построению веб-приложений, который позволяет асинхронно обмениваться данными с сервером в фоновом режиме без полной перезагрузки веб-страницы.

REST API (Representational State Transfer Application Programming Interface) — это архитектурный стиль взаимодействия клиента и сервера, использующий стандартные методы HTTP (GET, POST, PUT, DELETE) и передающий данные чаще всего в формате JSON.

9. Чем асинхронный запрос отличается от синхронного?
Синхронный запрос блокирует выполнение основного потока (UI-потока) браузера до тех пор, пока сервер не пришлет ответ. В это время страница «зависает», пользователь не может кликать на элементы или скроллить.

Асинхронный запрос выполняется в фоновом режиме. Основной поток продолжает работу, интерфейс остается отзывчивым, а результат обработки запроса обрабатывается, когда он будет готов (с помощью колбэков, промисов или async/await).

10. Что возвращает fetch()?
Функция fetch() возвращает Promise (промис), который разрешается объектом ответа (Response) после того, как сервер вернет заголовки ответа (даже если сервер вернул ошибку, например, 404 или 500).

11. Для чего нужны async и await?
Ключевые слова async и await — это синтаксический сахар поверх промисов, который позволяет писать асинхронный код в синхроподобном (последовательном) стиле.

async перед функцией делает её асинхронной (она автоматически возвращает промис).

await приостанавливает выполнение асинхронной функции до тех пор, пока указанный промис не выполнится (fulfilled или rejected), делая код чище и избавляя от цепочек .then().

12. Почему следует проверять response.ok?
fetch() считает запрос успешным, если сервер вообще ответил (даже кодами 404 Not Found или 500 Internal Server Error). Свойство response.ok принимает значение true, только если HTTP-статус ответа находится в диапазоне от 200 до 299. Проверка response.ok позволяет вовремя отловить логические ошибки сервера и перенаправить выполнение в блок catch.

13. Что делает response.json()?
Метод response.json() читает тело ответа от сервера (в формате сырого текста) и асинхронно распарсивает его из строки JSON в полноценный объект или массив JavaScript, возвращая новый промис с полученными данными.

14. Как обработать ошибку сети?
Ошибки сети (например, полное отсутствие интернета, обрыв связи, недоступность хоста) приводят к отклонению (rejection) промиса fetch(). Их обрабатывают с помощью блока try...catch:

JavaScript
try {
  let response = await fetch(url);
  // ...
} catch (error) {
  console.error("Ошибка сети или запроса:", error.message);
}
15. Что такое CORS?
CORS (Cross-Origin Resource Sharing, совместное использование ресурсов между разными источниками) — это механизм безопасности браузеров, который блокирует веб-страницам выполнение запросов к домену, отличному от домена, с которого была загружена сама страница, если сервер явно не разрешил такой доступ с помощью специальных HTTP-заголовков (Access-Control-Allow-Origin).

16. Чем отличаются GET и POST?
GET предназначен для получения (чтения) данных с сервера. Параметры передаются в строке URL. Запросы безопасны, идемпотентны и могут кэшироваться.

POST предназначен для отправки или создания новых данных (например, отправка формы, регистрация). Данные передаются в теле (body) запроса, запрос не идемпотентен и не кэшируется по умолчанию.

17. Почему нельзя доверять содержимому ответа сервера?
Данные, приходящие от сервера, могут быть скомпрометированы, содержать вредоносные скрипты (XSS), иметь поврежденную или неожиданную структуру (отсутствие обязательных полей, неверный тип данных). Доверять им нельзя, поэтому необходимо валидировать данные, обрабатывать исключения через try...catch и безопасно вставлять их в DOM (например, используя textContent, а не innerHTML).

18. Как показать индикатор загрузки?
Индикатор загрузки реализуется путем программного управления интерфейсом:

Перед отправкой запроса включают индикатор (например, устанавливают status.textContent = "Загрузка...", показывают спиннер, блокируют кнопку отправки через button.disabled = true).

В блоке finally или после успешного/неуспешного завершения запроса скрывают индикатор и возвращают элементы управления в исходное состояние (button.disabled = false).

19. Для чего нужен AbortController?
AbortController позволяет отменять запущенные асинхронные операции (включая активные fetch-запросы). Это критически важно при реализации быстрого поиска (debounce), когда пользователь продолжает вводить символы, а старые неактуальные запросы к серверу необходимо принудительно прервать, чтобы сэкономить трафик и избежать гонки данных (race conditions).
